# Quartal-Review-Protokoll
**Wann:** Letzter Sonntag jedes Quartals | **Dauer:** 2-3 Stunden
**Zweck:** Das System selbst verbessern — nicht nur Creator-Performance reviewen

---

## Block 1 — Creator-Portfolio (60 min)

### Für jeden aktiven Creator:

```
Creator: @___________

Performance-Trend (Quartal):
  PS-Durchschnitt Q-Anfang: ___  →  Q-Ende: ___  (Δ ___ %)
  LQS-Durchschnitt Q-Anfang: ___  →  Q-Ende: ___ (Δ ___ %)
  Follower Q-Anfang: ___  →  Q-Ende: ___  (Δ ___ %)
  Leads generiert: ___

Status:
  [ ] Wächst    → Weiter wie gehabt
  [ ] Plateau   → Decay-Protokoll + neue Season starten
  [ ] Schrumpft → Nischen-Pivot prüfen oder Offboarding
  [ ] Selbstlaufend → Auf Quarterly-Only reduzieren

Winning-Playbook (was hat diesen Quartal konsistent funktioniert):
  Hook-Typ:   ___
  Länge:      ___
  CTA:        ___
  Format:     ___
  Bestes Thema-Cluster: ___

→ In KNOWLEDGE_DATABASE.md eintragen
```

---

## Block 2 — Cross-Creator-Muster (45 min)

```
Welcher Hook-Typ hat in ≥ 50% der Creator gewonnen?
  _______________  → Neue Standard-Hypothese für Zyklus 1 aller Creator

Welches Format hat plattformübergreifend am besten funktioniert?
  _______________  → In SYSTEM_CORE.md updaten

Welche CTA-Formulierung hatte höchsten LQS im Schnitt?
  _______________  → Standard-CTA für Onboarding-Template

Welche Nische wächst am schnellsten?
  _______________  → Akquise-Fokus für Q+1

Welche Nische stagniert trotz System?
  _______________  → Nischen-Analyse oder Rückzug

Was hätte ich vor 3 Monaten wissen wollen?
  _______________  → Als Onboarding-Hinweis dokumentieren
```

---

```

LQS-Formel validieren:
  Hat LQS tatsächlich Funnel-Qualität vorhergesagt?
  Correlation: ___
  Anpassung nötig: [ ] JA → neue Gewichtung: ___  [ ] NEIN

Benchmark-Update (falls Blueprint neue Daten liefert):
  Neue CR-Benchmark TikTok: ___  (alt: 70%)
  Neue SR-Benchmark:        ___  (alt: 2%)
  Quelle: ___

Zyklus-Hierarchie anpassen?
  Gibt es Evidenz dass eine andere Variable-Reihenfolge besser ist?
  [ ] JA → neue Hierarchie: ___  [ ] NEIN

KNOWLEDGE_DATABASE-Qualität:
  Wie viele Einträge sind outdated oder widerlegt?
  ___  → Diese Einträge archivieren/löschen
```

---

## Output des Quartal-Reviews

```
Nach dem Review muss Folgendes aktualisiert sein:

[ ] KNOWLEDGE_DATABASE.md — neue Winning-Playbooks eingetragen
[ ] SYSTEM_CORE.md — falls Algorithmus-Änderungen
[ ] GROWTH_LOOP_SYSTEM.md — PS/LQS-Formel angepasst falls nötig
[ ] Nischen-Profile — neue Daten aus abgeschlossenen Creatorn
[ ] Creator-Dateien — Status + Playbook aktualisiert
[ ] Q+1 Prioritäten-Liste — wer bekommt welche Aufmerksamkeit
```
